**recipe/[slug].vue** — Currently throws createError on fetch failure (shows Nuxt error page). Change the data fetching approach:
- Replace the current `await useFetch` + `throw createError` pattern with a `useLazyFetch` or keep `useFetch` but add `pending` state handling.
- Actually, since this page uses SSR `await useFetch`, the skeleton won't show during SSR. Instead, wrap the entire template in a `<Suspense>` alternative: use `useLazyAsyncData` pattern so the page renders immediately with a skeleton, then fills in data. Specifically:
  - Change `await useFetch<Recipe>` to `useLazyFetch<Recipe>` (remove await).
  - Add `const pending = ...` from the return.
  - Move the `createError` throws into a `watch` on `error` that calls `showError()`.
  - In template: Show `<RecipeDetailSkeleton />` when `pending && !recipe`.
  - Show existing template content when `recipe` exists.
  - Show ErrorMessage when `error && !recipe` with retry that calls `refresh()`.

NOTE: This is a significant change. If `useLazyFetch` breaks SEO (since recipe detail pages need SSR for meta tags), instead keep `await useFetch` for SSR but add a client-side error handling fallback. The SEO meta tags already use `useServerSeoMeta` which runs on server, so they need the data during SSR. **Therefore, keep the current SSR pattern but enhance the error display**: Replace the `throw createError` with a softer error state that shows ErrorMessage with retry instead of navigating to the Nuxt error page. Use a local `fetchError` ref and show ErrorMessage when it's set.
