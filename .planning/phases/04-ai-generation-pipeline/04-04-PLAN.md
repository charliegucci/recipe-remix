```typescript
type AnalyticsEventType =
  | 'recipe_generated'
  | 'recipe_generation_failed'
  | 'recipe_viewed'
  | 'recipe_favorited'
  | 'recipe_unfavorited'
  | 'recipe_rated'

  | 'image_generation_failed'

interface AnalyticsEventInput {
  eventType: AnalyticsEventType
  userId?: string | null
  recipeId?: string | null
  metadata?: Record<string, any>
}
```

**`logAnalyticsEvent(db: Database, input: AnalyticsEventInput): void`**
- Fire-and-forget: does NOT return a promise the caller awaits
- Internally wraps the DB insert in a .catch(() => {}) -- analytics should NEVER crash the caller
- Insert into analyticsEvents with crypto.randomUUID() as id, JSON.stringify for metadata
- Pattern: `db.insert(schema.analyticsEvents).values({...}).catch(() => {})` -- swallow all errors

This utility will be called from the generate endpoint, image endpoint, and other places. It must have zero impact on request latency or reliability.

**server/api/analytics/events.post.ts:**

Client-side event ingestion endpoint for events that originate from the browser (e.g., recipe_viewed):
- Accept body: `{ eventType: string, recipeId?: string }`
- Only allow safe event types from client: 'recipe_viewed', 'recipe_favorited', 'recipe_unfavorited'
- Get userId from session if authenticated (optional -- guests can log views too)
- Call logAnalyticsEvent
- Return 202 (accepted) immediately
- No authentication required (views are tracked for everyone)

**server/api/analytics/dashboard.get.ts:**

Dashboard data endpoint (INFR-03):
- Require authentication (admin-level check is out of scope for v1 -- any authenticated user can see dashboard for now)
- Query analyticsEvents table with aggregations:
  1. **Generation stats (last 30 days):**
     - Total generation attempts: COUNT where eventType = 'recipe_generated' OR 'recipe_generation_failed'
     - Successful: COUNT where eventType = 'recipe_generated'
     - Failed: COUNT where eventType = 'recipe_generation_failed'
     - Success rate: successful / total * 100
  2. **Interaction stats (last 30 days):**
     - Total recipe views: COUNT where eventType = 'recipe_viewed'
     - Total favorites: COUNT where eventType = 'recipe_favorited'
     - Total ratings: COUNT where eventType = 'recipe_rated'
  3. **Recent events (last 50):**
     - Select from analyticsEvents ORDER BY createdAt DESC LIMIT 50
     - Parse metadata JSON before returning

- Use raw SQL via Drizzle's `db.select()` with `count()` and `eq()` for aggregations, or use `sql` template for complex queries.
- Return JSON: `{ generation: { total, successful, failed, successRate }, interactions: { views, favorites, ratings }, recentEvents: [...] }`
- Cache result in KV with 5-minute TTL (dashboard data does not need to be real-time)
