- Build the image prompt using buildImagePrompt
- Call `hubAI().run('@cf/black-forest-labs/flux-1-schnell', { prompt: imagePrompt })` which returns a ReadableStream or Uint8Array of image bytes

Note: NuxtHub uses `hubBlob()` for R2 access (not raw R2 bindings). The blob is already configured in nuxt.config.ts. The stored blob will be accessible via `/_hub/blob/{pathname}` or the public blob URL.

**server/api/recipes/[id]/image.post.ts:**

Create a POST /api/recipes/:id/image endpoint that triggers image generation for an existing recipe:
- Require authentication (same pattern as other user endpoints)
- Read recipe from DB by ID. Return 404 if not found.
- Only allow image generation for ai_generated recipes (return 400 for curated)
- If recipe already has imageKey, return 200 with existing imageKey (no regeneration)
- Call generateAndStoreImage with recipe data
- If successful, update recipe row in D1 setting imageKey
- Invalidate KV cache for this recipe
- Return 200 with { imageKey } or 500 with { error } on failure

This endpoint exists so the frontend can trigger image generation independently (e.g., if initial generation failed or was skipped).

**Update server/api/recipes/generate.post.ts:**

After step 9 (save recipe to D1), add a fire-and-forget image generation call:
- Call generateAndStoreImage(...) but do NOT await it at the top level
- Use a pattern like:
  ```typescript
  // Fire-and-forget: generate image in background
  generateAndStoreImage(recipeId, recipe.title, recipe.description, recipe.cuisineTags)
    .then(async (result) => {
      if (result.success && result.imageKey) {
        // Update recipe with imageKey
        await db.update(schema.recipes)
          .set({ imageKey: result.imageKey })
          .where(eq(schema.recipes.id, recipeId))
      }
    })
    .catch(() => {}) // Swallow errors - image is non-critical
  ```
- The generate endpoint returns the recipe immediately without waiting for the image
- The recipe detail page will show a placeholder if imageKey is null, and the image when it becomes available

Note: In the Cloudflare Workers environment, fire-and-forget promises may not complete after the response is sent. If this is an issue, the standalone endpoint (above) is the fallback -- the frontend can call it after receiving the recipe. Include a comment noting this limitation.
