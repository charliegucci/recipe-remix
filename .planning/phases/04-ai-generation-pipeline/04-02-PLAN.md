<task type="auto">
  <name>Task 2: Create the AI recipe generation endpoint</name>
  <files>server/api/recipes/generate.post.ts</files>
  <action>
Create POST /api/recipes/generate endpoint. This is the core pipeline that handles GEN-01, GEN-02, SAFE-01 through SAFE-04.

**Request body:** `{ ingredients: string[], cuisines: string[], restrictions: string[] }`
- ingredients: array of pantry ingredient names (required, min 2)
- cuisines: array of cuisine preferences (required, min 1, max 3). Support: "Italian", "Mexican", "Japanese", "Thai", "Indian", "Chinese", "Korean", "French", "Mediterranean", "Middle Eastern", "American", "Ethiopian", "surprise" (random pick)
- restrictions: array of dietary restrictions (optional)

**Authentication:** Require authenticated user (not anonymous). Use the same auth pattern as existing user endpoints -- check session, return 401 if not authenticated. Get userId from session.

**Pipeline steps:**

1. **Validate input** - Check ingredients array has 2+ items, cuisines has 1+ items. Return 400 with clear error if invalid.

2. **Create generation history record** - Insert into generationHistory with status 'generating', store input ingredients and cuisines. Use crypto.randomUUID() for ID.

3. **Build prompt** - Call buildRecipePrompt with ingredients, cuisines (handle "surprise" by picking 2 random cuisines), restrictions.

4. **Call Workers AI** - Use `hubAI().run('@cf/meta/llama-3.1-70b-instruct', { messages: [{ role: 'user', content: prompt }], max_tokens: 2048 })`. Wrap in try/catch. On failure, update generation history to 'failed', return 500 with user-friendly error.

5. **Parse response** - Call parseRecipeResponse. If parsing fails, retry the LLM call ONCE with a stricter prompt ("Your previous response was not valid JSON. Please return ONLY the JSON object."). If second attempt fails, update history to 'failed', return 422 with "Could not generate a valid recipe. Please try again."

6. **Validate ingredients (SAFE-01, SAFE-04)** - Call validateIngredients(db, recipe.ingredients). If invalid, update history to 'failed' with error listing unresolved ingredients, return 422 with { error: "Some ingredients could not be verified", unresolved: [...] }.

7. **Check dietary restrictions (SAFE-02)** - Call checkDietaryRestrictions(recipe.ingredients, restrictions). If violations found, update history to 'failed', return 422 with { error: "Recipe violates dietary restrictions", violations: [...] }.

8. **Inject safety temps (SAFE-03)** - Call injectSafetyTemps(recipe.instructions, recipe.ingredients). Use the returned modified instructions.

9. **Save recipe to D1** - Insert into recipes table with:
   - id: crypto.randomUUID()
   - source: 'ai_generated'
   - All parsed fields (title, description, ingredients as JSON string, instructions as JSON string, cuisineTags as JSON string, dietaryTags as JSON string, cookTime, difficulty)
   - imageKey: null (image generated async in Plan 03)
   - featured: false

10. **Update generation history** - Set status 'completed', recipeId, completedAt.

11. **Invalidate KV cache** - Delete recipe listing cache keys if any.

12. **Return response** - Return 201 with { recipe: fullRecipeObject, generationId }.

**Error handling (INFR-02):** Every step that can fail has a try/catch. Errors update generationHistory status to 'failed' with errorMessage. User-facing errors are descriptive but non-technical.

Use relative imports for all server utils. Follow existing API patterns (useDrizzle(event), hubKV(), etc.).
