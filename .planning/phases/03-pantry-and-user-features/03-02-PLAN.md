**Ingredient Search API** (`server/api/ingredients/search.get.ts`):
- Accept query param `q` (minimum 2 characters)
- Search ingredients table using LIKE '%query%' on both `name` and `commonNames` fields
- Return top 10 matches, prioritizing exact prefix matches first (name LIKE 'query%'), then contains matches
- Cache results in KV with key `ingredients:search:{query}` and 24-hour TTL (ingredient list is static)
- Return array of `{ id, name, category }`
- If `q` is empty or < 2 chars, return empty array

**Pantry GET** (`server/api/user/pantry/index.get.ts`):
- Require authenticated non-anonymous user via `getAuth().api.getSession()`
- Return all pantry items for the user, ordered by addedAt desc
- Return array of `{ id, ingredientId, ingredientName, addedAt }`

**Pantry POST** (`server/api/user/pantry/index.post.ts`):
- Require authenticated non-anonymous user
- Accept body `{ ingredientId: string, ingredientName: string }`
- Check for duplicate (same userId + ingredientId), return 409 if exists
- Generate UUID with `crypto.randomUUID()`, insert into pantryItems
- Return the created item with 201 status

**Pantry DELETE** (`server/api/user/pantry/[id].delete.ts`):
- Require authenticated non-anonymous user
- Delete pantry item by id, verify it belongs to the requesting user
- Return 204 on success, 404 if not found or not owned

**Dietary Restrictions GET** (`server/api/user/dietary-restrictions/index.get.ts`):
- Require authenticated non-anonymous user
- Return array of active restriction strings for the user: `['vegetarian', 'gluten-free']`

**Dietary Restrictions POST** (`server/api/user/dietary-restrictions/index.post.ts`):
- Require authenticated non-anonymous user
- Accept body `{ restrictions: string[] }` where each is one of: vegetarian, vegan, gluten-free, dairy-free, nut-free
- Validate restriction values against allowed list
- Replace all existing restrictions for user (delete all, insert new set) -- this is a "sync" operation
- Return the new restriction list

For auth checks, use the established pattern:
```typescript
const session = await getAuth().api.getSession({ headers: event.headers })
if (!session?.user || session.user.isAnonymous) {
  throw createError({ statusCode: 401, message: 'Authentication required' })
}
```

Use relative imports for server modules: `import { useDrizzle, schema } from '../../utils/drizzle'` (adjust depth per file location).

**usePantry composable** (`app/composables/usePantry.ts`):
- Use VueUse `useLocalStorage` with `initOnMounted: true` for guest storage (SSR-safe)
- Guest pantry: `useLocalStorage<Array<{id: string, name: string}>>('guest_pantry', [])`
- Guest dietary: `useLocalStorage<string[]>('guest_dietary_restrictions', [])`
- Authenticated pantry: `useFetch('/api/user/pantry')` (conditional on session)
- Authenticated dietary: `useFetch('/api/user/dietary-restrictions')` (conditional on session)
- Expose unified interface: `pantry`, `dietaryRestrictions`, `addIngredient(id, name)`, `removeIngredient(id)`, `toggleRestriction(restriction)`, `isInPantry(ingredientId)`
- For guests: mutate localStorage arrays directly
- For auth users: call API endpoints then refresh data
- Use `useSession()` from Better Auth client to determine storage mode
- Export: `usePantry()`

Install @vueuse/core first: `npm install @vueuse/core`

**IngredientAutocomplete component** (`app/components/IngredientAutocomplete.vue`):
- Text input with v-model bound to `searchQuery` ref
- Use VueUse `refDebounced(searchQuery, 300)` for debounced API calls
- Fetch from `/api/ingredients/search?q={debouncedQuery}` using `useFetch` with `watch: [debouncedQuery]`
- Show "Searching..." immediately when searchQuery !== debouncedQuery (optimistic loading indicator)
- Display dropdown list of results below input
- Each result shows ingredient name and category badge
- On click/select: emit `select` event with `{ id, name, category }`
- Clear input after selection
- Close dropdown on blur (with small delay for click to register)
- Handle empty state: "No ingredients found" when query >= 2 chars but no results
- Handle minimum: "Type at least 2 characters" when query < 2 chars
- Mobile-first: full-width input, touch-friendly dropdown items (min-h-12)
