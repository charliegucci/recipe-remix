<task type="auto">
  <name>Task 2: Add Cache-Control headers to recipe API endpoints</name>
  <files>
    server/api/recipes/[idOrSlug].get.ts
    server/api/recipes/index.get.ts
    server/api/recipes/featured.get.ts
  </files>
  <action>
Add HTTP Cache-Control headers to recipe API endpoints so Cloudflare's CDN can cache responses at the edge, reducing TTFB for repeat visitors.

1. **server/api/recipes/[idOrSlug].get.ts** (single recipe):
   - After the return statement (both cached and fresh paths), add cache headers using `setResponseHeaders`:
     ```typescript
     setResponseHeaders(event, {
       'Cache-Control': 'public, max-age=300, s-maxage=3600, stale-while-revalidate=86400'
     })
     ```
   - Strategy: Browser caches 5 min (max-age=300), CDN caches 1 hour (s-maxage=3600), stale-while-revalidate 24 hours.
   - Place `setResponseHeaders` BEFORE `return cached` and BEFORE `return recipe` (both code paths).

2. **server/api/recipes/index.get.ts** (recipe list/browse):
   - Add same pattern but shorter CDN TTL since browse results change with new recipes:
     ```typescript
     setResponseHeaders(event, {
       'Cache-Control': 'public, max-age=60, s-maxage=300, stale-while-revalidate=3600'
     })
     ```

3. **server/api/recipes/featured.get.ts** (featured recipes):
   - Featured changes infrequently, use longer TTL:
     ```typescript
     setResponseHeaders(event, {
       'Cache-Control': 'public, max-age=300, s-maxage=3600, stale-while-revalidate=86400'
     })
     ```

4. Do NOT add cache headers to:
   - User-specific endpoints (favorites, pantry, history) — these are personalized
   - POST/DELETE endpoints — mutations must not be cached
   - Auth endpoints — sensitive data

5. Run `npm run build` to verify.
  </action>

- `grep -r 'Cache-Control' server/api/recipes/` shows headers in all 3 GET endpoints
- `grep -r 's-maxage' server/api/recipes/` confirms CDN cache directives present
  </verify>
