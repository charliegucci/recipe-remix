  <action>
1. Install Lighthouse CI CLI as a dev dependency:
   ```bash
   npm install --save-dev @lhci/cli
   ```

2. Create `lighthouserc.js` in the project root:
   ```javascript
   module.exports = {
     ci: {
       collect: {
         url: [
           'http://localhost:3000/',
           'http://localhost:3000/recipe/thai-italian-pasta'
         ],
         numberOfRuns: 3,
         startServerCommand: 'npm run preview',
         startServerReadyPattern: 'Local:',
         startServerReadyTimeout: 30000
       },
       assert: {
         preset: 'lighthouse:recommended',
         assertions: {
           // Performance score must be 95+
           'categories:performance': ['error', { minScore: 0.95 }],

           // Core Web Vitals (2026 thresholds)
           'largest-contentful-paint': ['error', { maxNumericValue: 2500 }],
           'cumulative-layout-shift': ['error', { maxNumericValue: 0.1 }],

           // INP replaced FID — Lighthouse uses TBT as proxy
           'total-blocking-time': ['error', { maxNumericValue: 200 }],

           // Image optimization checks
           'uses-optimized-images': 'warn',
           'modern-image-formats': 'warn',
           'unused-javascript': 'warn',
           'uses-responsive-images': 'warn',

           // Relax some rules that are less relevant for SPAs
           'unsized-images': 'warn',
           'offscreen-images': 'off'
         }
       },
       upload: {
         target: 'temporary-public-storage'
       }
     }
   }
   ```

   Notes:
   - Use `thai-italian-pasta` as the test slug (it's a seeded recipe likely to exist).
   - The browse page (/recipes or similar) is not a separate route — the home page IS the browse page.
   - `startServerCommand: 'npm run preview'` builds and serves the production bundle locally.
   - `startServerReadyPattern: 'Local:'` matches Nitro's ready message.
   - `offscreen-images: 'off'` because NuxtImg handles lazy loading.
   - INP is not directly measurable by Lighthouse — Total Blocking Time (TBT) is the lab proxy.

3. Create `.github/workflows/lighthouse.yml`:
   ```yaml
   name: Lighthouse CI
   on:
     pull_request:
       branches: [main]

   jobs:
     lighthouse:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4

         - name: Setup Node.js
           uses: actions/setup-node@v4
           with:
             node-version: '20'
             cache: 'npm'

         - name: Install dependencies
           run: npm ci

         - name: Build
           run: npm run build
           env:
             NUXT_HUB_PROJECT_KEY: ${{ secrets.NUXT_HUB_PROJECT_KEY }}

         - name: Run Lighthouse CI
           run: npx lhci autorun
           env:
             LHCI_GITHUB_APP_TOKEN: ${{ secrets.LHCI_GITHUB_APP_TOKEN }}
   ```

   Notes:
   - Runs on PRs to main only (not on push, to save CI minutes).
   - LHCI_GITHUB_APP_TOKEN is optional — results upload to temporary public storage without it.
   - Build requires NUXT_HUB_PROJECT_KEY for NuxtHub module resolution.

4. Add a convenience script to package.json:
   ```json
   "lighthouse": "lhci autorun"
   ```

5. Run `npm run build` to verify the project still builds with @lhci/cli installed.

6. Optionally run `npx lhci autorun` locally to verify the configuration works (requires a successful build first). If the local environment lacks D1/KV bindings for preview, document this limitation — CI will run against the built preview server.
