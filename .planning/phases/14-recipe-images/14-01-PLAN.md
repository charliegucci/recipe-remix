<task type="auto">
  <name>Task 1: Create _seed-recipe-images endpoint for non-featured curated recipes</name>
  <files>server/api/_seed-recipe-images.post.ts</files>
  <action>
Create `server/api/_seed-recipe-images.post.ts` following the same structure as `_seed-images.post.ts` but using `generateAndStoreImage` (from `../../utils/image-generation`) instead of fetching from Unsplash.

The endpoint must:
1. Query all curated recipes where `featured = false` from D1 using `useDrizzle(event)` and the `recipes` table from `../../db/schema` (import eq from drizzle-orm).
2. For each recipe, call `generateAndStoreImage(recipe.id, recipe.title, recipe.description || '', JSON.parse(recipe.cuisineTags || '[]'))` — this function never throws, always returns `{ success, imageKey?, error? }`.
3. Store images at `recipes/curated/{recipeId}.png` — NOTE: `generateAndStoreImage` internally uses `recipes/ai-generated/{id}.png`. To use the curated path, call `hubAI().run('@cf/black-forest-labs/flux-1-schnell', { prompt })` directly inside the loop, convert the base64 response using the same pattern as `image-generation.ts`, then upload via `hubBlob().put('recipes/curated/' + recipe.id + '.png', imageBytes, { contentType: 'image/png' })`. Then update D1 with the curated blob path.
4. Skip recipes that already have a blob-path imageKey (path starts with `recipes/`) — only process those with null or picsum imageKey.
5. After updating D1 for each recipe, invalidate KV caches: `recipes:list:*` keys can't be batch-deleted by prefix in Workers KV — instead call `hubKV().del('recipes:list:all:1')` through `hubKV().del('recipes:list:all:4')` (covers 4 pages) and `hubKV().del('recipes:list:italian:1')` etc for each category. Alternatively, do a single `hubKV().del('recipes:featured')` plus individual `hubKV().del('recipe:' + recipe.id)` for each processed recipe.
6. Return `{ success: true, generated: N, skipped: N, failed: N, results: [...] }` with per-recipe status.

Important: AI generation for 22 recipes sequentially may take ~2-4 minutes total (flux-1-schnell ~5-8s per image). This is acceptable for a seed endpoint.

Rate limiting: Add a 200ms delay between AI calls using `await new Promise(r => setTimeout(r, 200))` to avoid hammering the Workers AI endpoint.

Error handling: Same graceful-skip pattern as `_seed-images.post.ts` — log error, push to results as failed, continue loop.

Do NOT import from `image-generation.ts` since that hardcodes the `ai-generated` path. Inline the AI call and blob upload logic using the curated path.
