<task type="auto">
  <name>Task 2: Configure branch protection on main via GitHub API</name>
  <files></files>
  <action>
Use `gh api` to set branch protection rules on the `main` branch of `charliegucci/recipe-remix`:

```bash
gh api repos/charliegucci/recipe-remix/branches/main/protection \
  --method PUT \
  --input - << 'EOF'
{
  "required_status_checks": {
    "strict": true,
    "contexts": ["Bundle Size Check", "Lighthouse CI"]
  },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null
}
EOF
```

This requires:
- `required_status_checks` with the two CI job names from `.github/workflows/ci.yml`: "Bundle Size Check" and "Lighthouse CI"
- `strict: true` means branch must be up to date before merging
- `enforce_admins: false` so the repo owner can still push directly in emergencies
- No required reviewers (solo developer)
- No branch restrictions

If the API call fails due to permissions (free plan limitation), note this in the summary and suggest the user configure it manually via GitHub Settings > Branches > Add rule.

NOTE: GitHub free plan for private repos does NOT support branch protection. If the repo is private and on free plan, document the manual steps instead. Check repo visibility first:
```bash
gh repo view charliegucci/recipe-remix --json isPrivate
```
  </action>
  <verify>
```bash
# Verify branch protection is set
gh api repos/charliegucci/recipe-remix/branches/main/protection 2>&1 | head -20
```
If protection is active, the response will include `required_status_checks`. If it returns 404 or error, branch protection was not set (note in summary).
  </verify>
  <done>Branch protection configured on main requiring "Bundle Size Check" and "Lighthouse CI" status checks to pass before merge, OR manual setup steps documented if API call fails due to plan limitations.</done>
