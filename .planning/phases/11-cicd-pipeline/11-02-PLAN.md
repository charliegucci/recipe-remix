Rewrite the CI Gates workflow with two jobs that both work correctly for a NuxtHub project.

**Job 1: bundle-size** — Measure the server bundle from `nuxt build` output:
1. Checkout, setup-node (v20), npm ci
2. Run `npx nuxt build`
3. Measure the total size of `.output/server/` directory (the Worker bundle) using:
   ```bash
   # Find the main server entry and measure it
   TOTAL_SIZE=$(find .output/server -name '*.mjs' -o -name '*.js' | xargs cat | wc -c)
   GZIP_SIZE=$(find .output/server -name '*.mjs' -o -name '*.js' | xargs cat | gzip -c | wc -c)
   GZIP_MB=$(echo "scale=2; $GZIP_SIZE / 1048576" | bc)
   echo "Server bundle gzip size: ${GZIP_MB}MB ($GZIP_SIZE bytes)"
   # Fail if gzip > 3MB
   if [ "$GZIP_SIZE" -gt 3145728 ]; then
     echo "::error::Bundle size ${GZIP_MB}MB exceeds 3MB limit"
     exit 1
   fi
   echo "Bundle size OK: ${GZIP_MB}MB"
   ```
4. Remove ALL references to `wrangler deploy --dry-run` and `.wrangler/dist`

**Job 2: lighthouse** — Run Lighthouse CI with proper build:
1. Checkout, setup-node (v20), npm ci
2. Run `npx nuxt build` (Lighthouse's `startServerCommand: 'npm run preview'` needs the build output)
3. Run `npx lhci autorun` — this will read the existing `lighthouserc.cjs` config which:
   - Starts server via `npm run preview`
   - Tests homepage and a recipe detail page
   - Asserts performance >= 0.95, LCP <= 2500, CLS <= 0.1, TBT <= 200
4. No `LHCI_GITHUB_APP_TOKEN` needed — using `temporary-public-storage` upload target (already configured in lighthouserc.cjs)

Both jobs run in parallel (no dependencies between them).
