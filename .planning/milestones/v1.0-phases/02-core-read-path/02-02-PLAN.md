  <action>
Create two API routes with KV caching:

**1. server/api/recipes/index.get.ts**
- Accept query params: `category` (optional string), `page` (optional number, default 1)
- PAGE_SIZE = 12 (3 columns x 4 rows)
- KV cache key: `recipes:list:${category || 'all'}:${page}`
- Check KV first with `hubKV().getItem(cacheKey)`
- On miss, query D1:
  - If no category: select from recipes with LIMIT/OFFSET
  - If category: join with recipeCategories, filter by category
  - Order by createdAt descending
- Parse JSON fields (ingredients, instructions, cuisineTags, dietaryTags) before returning
- Cache result in KV with TTL 300 (5 minutes)
- Return array of recipe objects

**2. server/api/recipes/featured.get.ts**
- No query params
- KV cache key: `recipes:featured`
- Check KV first
- On miss, query D1 for recipes where featured = true, limit 5
- Parse JSON fields
- Cache with TTL 86400 (24 hours - featured rarely changes)
- Return array of recipe objects

Use the established patterns:
- `useDrizzle(event)` for database access
- `hubKV()` for KV access
- `eq()` from drizzle-orm for WHERE clauses
- `getQuery(event)` for query parameters
- `createError()` for error responses
  </action>

- `curl http://localhost:3000/api/recipes/featured` returns 5 featured recipes
- Second request to same endpoint is faster (served from KV)
