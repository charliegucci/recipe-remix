  <action>
**Review POST/PUT** (`server/api/user/reviews/[recipeId].post.ts`):
- Require authenticated non-anonymous user
- Accept body `{ rating: number, review?: string }`
- Validate: rating must be integer 1-5
- Validate: review text max 1000 characters if provided
- Upsert behavior: if user already has review for this recipe, UPDATE it (update rating, review, updatedAt). Otherwise INSERT new row with `crypto.randomUUID()` id.
- Use Drizzle's `insert().onConflictDoUpdate()` if possible, or check-then-insert/update pattern
- Note: The unique composite index on (userId, recipeId) enforces one review per user per recipe. Since it's an index not a constraint in the schema, use a select-then-insert/update approach.
- Return the created/updated review with 201/200

**Reviews GET for recipe** (`server/api/user/reviews/[recipeId].get.ts`):
- Public endpoint (no auth required) -- anyone can read reviews
- Return all reviews for the recipe, joined with users table to get reviewer name
- Include aggregate: `{ avgRating: number, totalReviews: number, reviews: Array<{ userId, userName, rating, review, createdAt }> }`
- Order reviews by createdAt desc
- Support `page` query param (PAGE_SIZE = 10)

**Update recipe detail API** (`server/api/recipes/[id].get.ts`):
- Add aggregate rating data to the existing recipe detail response
- Query userRecipeReviews table: COUNT and AVG(rating) for this recipe
- Add to response: `avgRating: number | null`, `totalReviews: number`
- Keep existing KV caching but ensure cache key includes review data (or use shorter TTL for detail pages with reviews -- 5 min)
- Do NOT break existing response shape -- add new fields alongside existing ones

Use relative imports. For the reviews GET endpoint, join with users table: `import { eq } from 'drizzle-orm'` and join on `userRecipeReviews.userId = users.id`.
  </action>

- `GET /api/recipes/{id}` now includes avgRating and totalReviews fields
- Review POST returns 401 for unauthenticated users
- Review GET works without auth</verify>

**StarRating component** (`app/components/StarRating.vue`):
- Props: `modelValue: number` (current rating, 0 = unrated), `readonly: boolean` (default false), `size: 'sm' | 'md' | 'lg'` (default 'md')
- Display 5 star icons using inline SVG (filled star = gold/amber-400, empty star = gray-300)
- Interactive mode (readonly=false): hover highlights stars up to cursor position, click emits `update:modelValue`
- Readonly mode: display only, no hover effects
- Support half-star display in readonly mode (for average ratings) -- use CSS clip-path or two overlapping stars
- Sizes: sm = w-4 h-4, md = w-5 h-5, lg = w-6 h-6
- Touch-friendly: entire star area is tappable

**ReviewForm component** (`app/components/ReviewForm.vue`):

- Submit button: "Submit Review" (or "Update Review" if editing)
- Loading state during submission
- On submit: POST to `/api/user/reviews/{recipeId}`
