  <action>
All endpoints require authenticated non-anonymous user (same auth check pattern as Plan 02).

**Favorites GET** (`server/api/user/favorites/index.get.ts`):
- Join userFavorites with recipes table to return full recipe objects
- Order by favorited date desc (newest first)
- Support optional `page` query param for pagination (PAGE_SIZE = 20)
- Return `{ recipes: Recipe[], hasMore: boolean }`

**Favorites POST** (`server/api/user/favorites/[recipeId].post.ts`):
- Extract recipeId from route params
- Verify recipe exists in recipes table (return 404 if not)
- Check if already favorited (return 409 if duplicate)
- Insert into userFavorites with userId and recipeId
- Return 201 with `{ favorited: true }`

**Favorites DELETE** (`server/api/user/favorites/[recipeId].delete.ts`):
- Extract recipeId from route params
- Delete from userFavorites where userId AND recipeId match
- Return 204 (idempotent -- no error if wasn't favorited)

**History GET** (`server/api/user/history/index.get.ts`):
- Join userRecipeHistory with recipes table
- Order by viewedAt desc (most recent first)
- Support `page` query param (PAGE_SIZE = 20)
- Return `{ recipes: Array<Recipe & { viewedAt: Date }>, hasMore: boolean }`

**History POST** (`server/api/user/history/index.post.ts`):
- Accept body `{ recipeId: string }`
- Verify recipe exists
- Insert new history entry (always creates new row -- multiple views tracked)
- Generate UUID for id
- Return 201

Use relative imports: `import { useDrizzle, schema } from '../../../utils/drizzle'` (adjust depth). Import `getAuth` from `'../../../lib/auth'`. Parse JSON fields on recipe objects before returning (ingredients, instructions, cuisineTags, dietaryTags -- same pattern as existing recipe API).

**useFavorites composable** (`app/composables/useFavorites.ts`):
- Fetch user's favorite recipe IDs on init (only if authenticated)
- Maintain a reactive Set of favorited recipe IDs for O(1) lookup
- `isFavorite(recipeId: string): boolean` -- check the Set
- `toggleFavorite(recipeId: string)` -- optimistic UI pattern:
  1. Immediately update local Set (add or remove)
  2. Call POST or DELETE API
  3. On error: revert the Set and refresh from server
- If user is not authenticated or is anonymous, return `requiresAuth: true` flag
- Export: `useFavorites()`

**useHistory composable** (`app/composables/useHistory.ts`):
- Fetch history with pagination support
- `recordView(recipeId: string)` -- fire-and-forget POST (don't block UI)
- Only record if user is authenticated and not anonymous
- Export: `useHistory()`

**FavoriteButton component** (`app/components/FavoriteButton.vue`):
- Props: `recipeId: string`
- Uses useFavorites composable
- Renders a heart icon (filled red when favorited, outline when not)

- On click: if authenticated, call toggleFavorite
