**useGenerate.ts changes:**

The actual API call (`POST /api/recipes/generate`) is synchronous — it returns the full recipe in one response. The status currently jumps from `generating` straight to `complete`. To show multi-step progress, simulate step transitions on the client during the await:

1. In `generate()`, BEFORE the `$fetch` call, set `status.value = 'generating'` and `startTime.value = Date.now()`.
2. Start a step progression timer that transitions status through the pipeline:
   - `generating` at 0s (already set)
   - `validating` after ~5s
   - `imaging` after ~12s (only if the API hasn't resolved yet)
3. Use `setTimeout` with cleanup. When the API call resolves (success or error), cancel any pending timers so status doesn't advance after completion.
4. On success, set `status.value = 'complete'` (this already happens). On error, set `status.value = 'error'`.
5. Store the step transition timestamps in a reactive ref `stepStartTimes: Record<string, number>` so GenerationProgress can compute per-step elapsed time.

Key: The step transitions are SIMULATED on the client side to match roughly what the server is doing. The actual generation takes ~15-25s total. The timers should be cancelled immediately when the real response arrives.

Also update `generate.vue`:
- **BLOCKER FIX — v-else-if guard:** The current condition on line ~131 is `v-else-if="status === 'generating' || status === 'validating'"`. This MUST be updated to also include `'imaging'`: `v-else-if="status === 'generating' || status === 'validating' || status === 'imaging'"`. Without this, GenerationProgress disappears when status advances to 'imaging', breaking the third step requirement of GENX-01.
- Pass `stepStartTimes` as a prop to `LazyGenerationProgress` alongside existing props. Add `:step-start-times="stepStartTimes"` to the component usage.

**resumeGeneration() limitation:** The `resumeGeneration()` function resumes from localStorage and polls the server — it does NOT populate `stepStartTimes` because the original step transition timestamps are lost across page reloads. The countdown timer will not display during resumed sessions. This is acceptable because resume is a rare edge case (page refresh mid-generation) and the progress steps still display correctly via status polling — only the per-step countdown is absent.

**GenerationProgress.vue changes:**

Rebuild the component with these enhancements:

1. **Props:** Add `stepStartTimes` prop typed as `Record<string, number>` via `defineProps`. This must be declared in `defineProps` alongside existing props (status, errorMessage, startTime).

**BLOCKER FIX — Remove existing timer system:** The current GenerationProgress.vue has an elapsed ref, a timer variable, a watch block (lines ~46-63 that track `props.startTime` and run `setInterval`), and an `estimatedRemaining` computed (lines ~66-86). These ALL must be REMOVED before adding the new per-step countdown. If left in place, the old timer and the new per-step countdown will produce conflicting/duplicate countdown displays. Specifically remove:
   - `const elapsed = ref(0)` and `let timer: ReturnType<typeof setInterval> | null = null`
   - The `watch(() => props.startTime, ...)` block
   - The `onUnmounted(() => { if (timer) clearInterval(timer) })` block
   - The `const estimatedRemaining = computed(...)` block
   - Any template references to `estimatedRemaining`

2. **Per-step countdown timer (GENX-03):**
   - Define step time estimates: `{ generating: 8, validating: 5, imaging: 12 }`.
   - For the ACTIVE step, compute remaining time as `estimate - (now - stepStartTimes[stepKey])` in seconds, updated every 500ms via an interval.
   - Display as "~Xs remaining" below the active step label. When remaining <= 0, show "Almost done...".
   - Only the active step shows the countdown — pending and completed steps do not.

3. **Distinct visual animations per step (GENX-02):**
   - **Active "generating" step:** Show a pulsing sparkles/magic-wand icon with a CSS `@keyframes sparkle` animation — scale 1 to 1.2 with opacity cycling, using amber/orange colors.
   - **Active "validating" step:** Show a rotating checkmark-shield icon with a CSS `@keyframes spin-slow` animation (one full rotation per 2s), using blue colors.
   - **Active "imaging" step:** Show a camera/photo icon with a CSS `@keyframes flash` animation — brief brightness pulse every 1.5s, using purple colors.
   - **Completed steps:** Green checkmark icon that appears with a `@keyframes scale-in` animation (scale 0 to 1 over 300ms with overshoot via cubic-bezier). IMPORTANT: The `scale-in` animation class must be applied ONLY to the completed step's checkmark icon element, NOT to active step icons.
   - **Pending steps:** Gray circle with dashed border, no animation.

4. **Step label styling:**
   - Active: bold, dark text, slightly larger (text-base vs text-sm), with the step's accent color.
   - Completed: normal weight, green text, strikethrough-like muted style.
   - Pending: light gray text.

5. **Overall progress bar (optional enhancement):**
   - Add a thin horizontal progress bar at the top that fills based on which step is active: generating = 0-33%, validating = 33-66%, imaging = 66-100%, complete = 100%.
   - Use `transition: width 500ms ease-out` for smooth fill animation.

6. **CSS:** Use scoped `<style>` block with the keyframe animations. Do NOT use external animation libraries — pure CSS keyframes + Tailwind utilities.
