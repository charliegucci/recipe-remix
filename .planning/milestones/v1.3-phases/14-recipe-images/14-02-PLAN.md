Audit the image display pipeline for non-featured recipes and fix any gaps:

**1. Check `app/pages/recipes.vue`:**
Read the file. Confirm that `imageKey` is included in the recipe data fetched from `/api/recipes` and passed to `RecipeCard`. If the API response or the `RecipeCard` prop interface is missing `imageKey`, add it. The `RecipeCard` component already accepts `imageKey: string | null` in its props — ensure `/api/recipes` returns this field and `recipes.vue` passes it through.

**2. Check `app/components/RecipeCard.vue`:**
Verify the `imageUrl` computed property and `onImageError` handler are present and correct:
- `imageUrl` returns `/api/images/${recipe.imageKey}` for blob paths (not starting with `http`)
- `onImageError` sets `imageLoadFailed = true`
- `showImage` computed checks both `imageUrl !== null` and `!imageLoadFailed`
- The gradient fallback `v-else` div renders when `!showImage`
If any of these are missing or broken, fix them. If all are correct, add a code comment confirming the fallback behavior.

**3. Check `server/api/_seed.post.ts` KV invalidation:**
The seed endpoint only invalidates `recipes:featured`. After a reseed, recipe list pages may be stale in KV. Add invalidation for common list cache keys: after the existing `kv.del('recipes:featured')`, also call:
```ts
await kv.del('recipes:list:all:1')
await kv.del('recipes:list:italian:1')
await kv.del('recipes:list:mexican:1')
await kv.del('recipes:list:asian:1')
await kv.del('recipes:list:american:1')
await kv.del('recipes:list:mediterranean:1')
```
Each in its own `try/catch` block or wrapped together — non-fatal.

**4. Check `app/components/FeaturedCarousel.vue`:**
Verify `getImageUrl` returns `/api/images/{blobPath}` for blob paths and `imageLoadFailed` Set tracks per-recipe failures. If correct, no changes needed.

Do not refactor or redesign components — make targeted fixes only. If a file is already correct, leave it unchanged and note it in the commit.
